# 妙响官方提示词规则 + 输出格式（风格提示词 / 歌词分离）+ 英文歌词标签规范

本章把「妙响平台官方/半官方的提示词规则」和「本技能强制的输出格式」合在一起。前半部分告诉你妙响的输入框长什么样、官方推荐怎么写；后半部分是铁规——**纯音乐只有提示词，带人声的歌必须把提示词拆成「风格提示词」和「歌词」两段，歌词用全英文方括号标签分段**。

> 规则来源：妙响官方教程整合手册（数据取自官方网站/官方帮助中心，2026-06）、NavCN / varoo 等以官方页面为准的条目、smzdm 以官方平台为例的「万能提示词公式」教程。平台界面会迭代，按钮名以实际页面为准；本章给的是**提示词层面的通用写法**。

---

## 一、妙响的两种创作模式（决定提示词怎么拆）

| 模式 | 输入框结构 | 适合 | 提示词要求 |
|---|---|---|---|
| **灵感创作** | 一个文本框，一句话/一段情绪描述 | 零基础、先找方向 | 口语化但要素齐全的单句复合描述，平台有「优化提示词」自动润色；一次出多个版本 |
| **专业模式** | **两个独立框**：①风格栏（风格提示词）②歌词框（自写或 AI 作词） | 有明确想法、要可控 | 风格栏 = 优化后的风格描述；歌词框 = 分段落、带英文结构标签的歌词 |

**纯音乐 / 伴奏**：走「纯音乐模式」或勾选无人声，**只有风格提示词，没有歌词框**。

> 关键结论：妙响专业模式天然就是**「风格 + 歌词」两栏分离**的。本技能要求把交付拆成这两段，不是自创格式，而是直接对齐平台输入框，让用户能**原样复制粘贴**——风格栏粘「风格提示词」，歌词框粘「带标签的歌词」。

## 二、妙响官方推荐的提示词写法

### 2.1 官方万能公式（来自以官方平台为例的教程）

```
音乐风格  +  情绪氛围  +  通用场景  +  乐器搭配
```

示例（官方示例改写）：
> 流行治愈风，温暖舒适，适合视频旁白和日常 Vlog，搭配小提琴、钢琴与轻柔鼓点，旋律干净通透，无复杂编曲，大众听觉友好。

### 2.2 官方推荐三段式（来自官方教程整合手册）

```
主题：[一句描述]  +  风格：[从预设模板选 / 自定]  +  情绪：[核心情绪词]
```

- 妙响是**中文界面**，可用中文自然描述，也可以选预设风格模板；
- 平台自带「**优化提示词**」功能，能把"伤感流行女声"这类口语润色成专业风格提示词——用户给得越短，越建议让他先点一次优化再生成。

### 2.3 官方预设风格模板（可直接挑，持续更新）

校园毕业季 · 国风赛博朋克 · Citypop 都市流行 · ACG 二次元 · Drift Phonk · Afrobeat · Techno · 独立摇滚 · Lo-fi · 伤感 EMO · 唢呐 · 中国打击乐 · 古风/国风 · 电子/EDM · 民谣 · 摇滚 · R&B · 说唱 等数十种。

> 给用户选项时，优先从官方预设里挑（识别度高、训练充分）；自定曲风要写成「主风格 + 融合元素」（如"国风为主，副歌融入轻量电子鼓"）。

## 三、风格提示词规则（填进「风格栏」的那段）

风格提示词 = 本技能「万能公式」的九要素（见 `../SKILL.md` 与 `01-prompt-anatomy.md`），**只描述声音，不写歌词、不写段落结构标签**。

1. **只放声音要素**：曲风、情绪、乐器、人声（性别/质感/音域）、制作质感、BPM、结构时长、负向约束。**结构标签（[Verse] 等）严禁放进风格栏**——它们属于歌词框，放错地方会被忽略或干扰模型。
2. **顺序即权重**：越靠前越重要。推荐顺序：`曲风 + 融合 → 场景/情绪 → 主奏乐器 → 人声 → BPM → 结构时长 → 质感 → 负向约束`。
3. **关键词驱动，不要写小作文**：用"melancholic, neo-soul, 78 BPM, rhodes, warm analog bass"这类短语，而不是"一首让我想起东京雨夜霓虹灯下想念某个人的伤感歌"。后者模型读得差。
4. **显式写 BPM**：不写 BPM 模型按曲风瞎猜，锁定更可控（卡点场景用 `08-advanced-techniques.md` 技巧 1 反推）。
5. **长度上限**：风格栏约 1000 字符为舒适上限，超过会被静默截断——**前排放最重要的描述**。纯音乐另有 ≤500 字符硬限制（见 `06-instrumental-playbook.md` 第一节）。
6. **人声写法**：在风格栏里写"女声温润带轻微气声，中音区，不炫技"；人声类型/唱法标签（[Female Vocal] 等）放进歌词框的段落上方，不进风格栏。

## 四、输出格式铁规（本技能强制）

**所有带人声的作品，交付的「直接复制」块必须拆成两段，顺序固定：**

```markdown
### 风格提示词
```
<风格栏内容：九要素声音描述，关键词驱动，≤约1000字符>
```

### 歌词
```
[Intro]
...
[Verse 1]
...
[Chorus]
...
[Outro]
...
```
```

- **纯音乐**：只有「风格提示词」一段，没有「歌词」段（见下面铁规 3）。
- 双版本/多版本：每个版本都各自跑「风格提示词 + 歌词」两段；或总体两段 + 一张版本差异表（只列差异项），但两段标题一个不能少。
- 灵感模式（用户只想一句话出歌）：仍先给完整两段作为"专业模式可直接粘贴版"，并附一句"也可以把整段意思浓缩成一句话丢进灵感创作框"。

### 铁规 1 · 纯音乐只有提示词
纯音乐 / 无人声 BGM 的交付，**只有「风格提示词」一段**，不出现「歌词」段。且全文 ≤500 字符（含标点空格），三处写死"纯音乐，无人声，不要哼唱"。

### 铁规 2 · 带人声必拆两段
带人声歌曲，提示词**必须**分成「风格提示词」+「歌词」。**不能把歌词揉进风格栏里当成一段长文**。两段分别复制进妙响的「风格栏」和「歌词框」。

### 铁规 3 · 歌词标签全英文
歌词里不同段落/不同唱法，**必须用全英文方括号元标签（metatags）标注**，不能用中文"主歌/副歌/桥段"当段名、也不能用中文括号。原因：妙响 / Suno 类引擎对方括号英文元标签识别最稳定；妙响 AI 作词默认输出的是中文段落名，**交付前需转成英文方括号标签**。

## 五、英文歌词标签规范（必抄）

### 5.1 结构标签（段落身份，每段独立成行，放在该段歌词正上方）

| 英文标签 | 中文含义 | 用法 |
|---|---|---|
| `[Intro]` | 前奏 | 开篇建立基调，可无人声 |
| `[Verse]` / `[Verse 1]` / `[Verse 2]` | 主歌 | 叙事主体，不同 Verse 歌词不同、旋律相近 |
| `[Pre-Chorus]` | 预副歌 | 副歌前的推进，制造期待 |
| `[Chorus]` | 副歌 / hook | 最抓耳、重复出现的核心记忆点 |
| `[Post-Chorus]` | 副歌后 | 副歌收束后的延伸段，常见流行 |
| `[Bridge]` | 桥段 | 中后段对比段，通常换旋律/调性，出现一次 |
| `[Interlude]` | 间奏 | 乐器过渡段，无词或有短吟唱 |
| `[Instrumental]` / `[Break]` | 纯乐器段 | 该段无 vocals |
| `[Hook]` | 钩子短句 | 一句洗脑短语，常嵌在副歌里 |
| `[Solo]` | 独奏 | 乐器/人声 solo  spotlight |
| `[Outro]` | 尾奏 | 收尾，常渐弱或重复短语 |

### 5.2 人声 / 唱法提示标签（放在段落标签下一行、歌词正上方，控制"谁唱、怎么唱"）

| 英文标签 | 含义 |
|---|---|
| `[Female Vocal]` / `[Male Vocal]` | 女声 / 男声 |
| `[Duet]` | 对唱 |
| `[Choir]` | 合唱 |
| `[Whispered]` | 气声/耳语 |
| `[Spoken]` | 念白/说唱 |
| `[Rap]` | 说唱 |
| `[Belted]` | 强混声爆发 |
| `[Falsetto]` | 假声 |
| `[Harmonized]` | 叠加和声 |
| `[Ad-lib]` | 即兴点缀 |

> 写法示例：`[Chorus]` 下一行 `[Belted]` 再写副歌歌词——让副歌更有力。一次别堆超过 2~3 个提示标签，多了模型反而不知道听谁的。

### 5.3 歌词格式纪律（决定旋律干不干净）

1. **每个标签独占一行**，前后不留空格；标签和歌词之间空一行再写词。
2. **段与段之间空一行**，让模型清楚"这段结束了、下一段开始"。
3. **副歌每次出现必须原样重复**（同词同旋律）。只写一次然后指望模型循环，结果会不一致——要么每段都贴全，要么用 `[Chorus] x2` 这类重复标记。
4. **一行一句**，一句一个意思；主歌 4~8 行、副歌 2~4 行最稳，别写成长段落。
5. **桥段要短**（2~4 行），太长稀释 hook。
6. **标签全英文、首字母大写、方括号**；`[verse 1]`、`(副歌)`、`【主歌】` 都不规范。

## 六、完整双段示例（可直接抄）

### 风格提示词
```
中文城市治愈抒情，深夜加完班打车回家的画面，情绪从疲惫慢慢转向释怀；钢琴为主、副歌加入温暖弦乐；温柔女声，带轻微气声，中音区，不炫技；BPM 82；结构 主歌—预副歌—副歌—桥段—副歌；整体干净通透，人声清晰不闷；不要电子炸裂编曲、不要过快节奏、不要 rap。
```

```

[Outro]
（Whispered）
晚安，慢慢走。
```

## 七、常见翻车与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 生成的歌没有清晰的副歌、像一锅粥 | 歌词没标 `[Chorus]`，模型猜结构 | 每段加英文结构标签，副歌原样重复 |
| 副歌每次回来都不一样 | 只写一次 `[Chorus]` 指望循环 | 每段都贴全副歌，或用 `[Chorus] x2` |
| 风格栏里写了 `[Verse] [Chorus]` | 结构标签放错框，被忽略/干扰 | 结构标签移到歌词框；风格栏只留声音描述 |
| 人声发闷/不对 | 风格栏没写清人声，或把人声标签写进风格栏 | 风格栏写"女声温润中音区"，人声类型标签写进歌词段上方 |
| 歌词像一段话、咬字糊 | 没分行、没标签 | 一行一句 + 英文标签独行 + 段间空行 |
| 风格栏被截断、重要描述丢了 | 超 ~1000 字符被静默截断 | 前排放最重要描述；纯音乐砍到 ≤500 |
| 发行时歌词里一堆标签 | 没清理就提交 | 发行前删掉方括号标签只留词（平台要求） |
