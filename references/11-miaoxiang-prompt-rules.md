# 妙响输入结构与输出格式规范（风格提示词 / 歌词）

> **来源分层（v2.0 修订）**：本章「平台机制、公式、参数」部分来自**官方知识库 32 篇精读**，权威出处与原文引文见 `12-official-guide.md`；「交付拆两段、五件套」等是**本技能自己的服务设计**，不是官方要求。
> 旧版本章引用的「官方教程整合手册 / NavCN / smzdm 万能公式」属第三方整理，现已全部替换。**平台界面会迭代，按钮名以实际页面为准。**

## 一、妙响的三种创作路径（决定提示词怎么拆）

官方路径三分（新手流程 `AaL9:29-36`）：

| 路径 | 输入结构 | 适合 | 提示词要求 |
|---|---|---|---|
| **Agent 模式** | 多轮对话 | 零基础、想边聊边定 | 对话中确认风格/情绪/音色 |
| **经典 · 灵感创作** | 一个文本框 | 一句话出歌 | 口语化但要素齐全的单句复合描述；可用「优化提示词」「随机灵感」「纯音乐开关」 |
| **经典 · 专业模式**（含「高级模式」） | **风格描述栏 + 歌词框** 两栏，另有人声性别/音色、模型选择、预设风格标签、参考音频、高级选项 | 有明确想法、要可控 | 风格栏 = 全局风格；歌词框 = 歌词或「分段提示词 ➕ 歌词」 |

**两栏分工**：
- 风格描述栏决定「听觉效果和音乐表现」，官方说「**也可以选择不填**」（`MVeB:131`）。
- 歌词框决定「文字内容和段落结构」，**纯音乐的官方开关也在这里**（见第三节）。
- ⚠️ 官方允许「风格底色 + 分段指令 + 歌词」混排进歌词框（`QCVK` 范式二、各曲风实操）。本技能要求「拆两段交付」只是**为了用户能原样分别粘贴**，不是官方禁令，也不代表两栏不能互相补位。

**模型**（官方全库核实）：音乐生成 **Sway v5.0 / v5.5**；AI MV 视频 **Seedance 2.0 / 2.5**。全库未出现 `SeedMusic`、`Mureka`；`Sodance` 是 Seedance 的拼写错误；Suno / Chirp 只出现在**第三方引用**里，不是妙响模型。

## 二、官方提示词公式（替代旧版「万能公式」「三段式」）

### 2.1 核心公式（`FKQK:244`）

```
[结构 + 风格 + 氛围 + 乐器 + 人声 + 其他细节]
```

组装四步：先定骨架（结构+风格）→ 再画皮肤（氛围+情绪）→ 然后穿衣（乐器+人声）→ 最后点缀（特效+细节）。官方示例：

```
[Verse][80s Synth-pop, nostalgic and dreamy, for a late-night drive, led by a classic synthesizer bassline and electronic drums, with breathy female vocals, lush reverb, subtle tape saturation]
```

### 2.2 按曲风分发的四条公式（官方不是一条公式打天下）

| 曲风 | 官方公式 |
|---|---|
| 动感流行 | `[速度BPM] + [核心节奏风格] + [标志性音色] + [人声质感] + [情感基调]` |
| 潮流电子 EDM | `[速度BPM] + [核心节奏风格] + [标志性音色] + [人声质感](选填) + [情感基调]` |
| 民族国韵 | `[细分曲风] + [核心民族乐器] + [西方现代乐器/节奏] + [情绪与意境] + [人声特征]` |
| 新世纪 Rap | `[风格定义] + [核心律动描述] + [人声质感细节] + [编曲空间动态] + [混音音质倾向]` |

另有「五核心要素」：`核心曲风 / 标志性乐器编配 / 音色与演唱技巧 / 制作与节奏特点 / 客观性`（`S03:44`）。客观性要求「描述必须专注于具体的音乐特征，**避免主观赞美或总结性评论**（不要说『一种伟大的声音』）」。

### 2.3 长度、字数、BPM

| 项 | 官方值 |
|---|---|
| 提示词长度 | **30-60 个词通常效果最好**，「不是越长越好」（`FKQK:262`） |
| 风格描述栏上限 | **2000 字**（`BKF:48`；另有历史版本 7000/1000 字截图，以界面为准） |
| 歌词栏上限 | **5000 字**（`BKF:48`；历史版本有 102400 字截图） |
| 高级选项 | 人声性别 / 风格权重 / 参考音频权重 / 创意发散程度，各 **1-10 档** |
| 参考音频 | 最多 **2 个**；改词保曲建议权重 **8-9**，风格权重与创意发散尽量低 |

> **没有「1000 字符会被静默截断」「500 字符硬限制」这类官方说法**，旧版已删。
> **BPM 不是必填**：动感流行/EDM 两条公式把 BPM 列在首位，卡点类可写；但 `WNB:124/342/494` 三处「**不建议使用 bpm 的提示词**，ai 会根据歌词长短自动匹配，强行设定会让歌词听起来特别赶」。抒情/写词类交给模型更稳。

### 2.4 权重与迭代（官方做法）

- 优先级词 `Dominated by / Led by / Focus on`；弱化词 `Subtle / In the background / A hint of`（`FKQK:387-388`）。
- **写死 vs 留白**：必须项写明 `male rap vocals`；想让 AI 发挥就用宽泛词 `keyboard melody` 而非 `piano melody`（`FKQK:259-260`）。
- **迭代只改 3-5 个词**，不要完全重写（`FKQK:389`）；一次生成两个版本、不原地覆盖历史版本（`Bu2:200`、`Dkd:27`）。
- 避免冲突描述：`A happy, sad, energetic, calm song` 这种是错的，只选一个主要情绪（`FKQK:386`）。
- 合规：不写知名艺人名，改述其风格特征（`FKQK:238`）。

## 三、纯音乐：走官方字段机制（旧版「三处无人声」已废止）

`XieP:366` 原文：

> 「如果要创作纯音乐，在歌词栏里输入 `[Inst]`、`[Instrumental]`、`[伴奏]`、`[纯音乐]` 即可，字段变灰即为生效～」

| 要点 | 出处 |
|---|---|
| 纯音乐**不需要** `[Verse]`/`[Chorus]` 段落 | `XieP:151` |
| 改编纯音乐 BGM「记得在**歌词里**输入『纯音乐』或 `Instrumental`」 | `Bu2:182` |
| 「用仅仅用中文提示词输入『伴奏』『纯音乐』还是会有一定概率会生成带人声旋律的歌曲…**建议全部使用英文提示词，或打开纯音乐按钮**」 | `Om77:68-70` |
| 风格关键词写 `Instrumental`；官方甚至允许 `Instrumental with Humming` 作氛围 | `XieP:280`、`JauM:251` |

**交付写法**（本技能约定）：
```
### 风格提示词（粘「风格栏」）
Instrumental, 轻快治愈的日常 vlog BGM，木吉他拨弦为主奏、竖琴短琶音为点缀、弦乐垫底，
明亮温暖，动态平缓不抢画面，BPM 112，60 秒可无缝循环，低频干净轻薄。

### 歌词栏指令（粘「歌词框」）
[Instrumental]
```
> 即：纯音乐**仍然要用到歌词框**，只是填的是字段而不是歌词。旧版「纯音乐只有风格提示词一段、不出现歌词段」的说法会让用户漏掉这一步，已更正。
> 中文「纯音乐」单词有概率失效 → **优先英文 `[Instrumental]` 或打开纯音乐开关**。不再要求三处重复「无人声」，也不再要求「不要哼唱」。

## 四、输出格式：本技能的两段式交付（服务设计，非官方要求）

**带人声作品**：「直接复制」拆成两块，顺序固定，分别粘贴到风格栏与歌词框。

```markdown
### 风格提示词（粘「风格栏」）
<全局声音描述：曲风 + 氛围 + 乐器 + 人声 + 质感；关键词驱动，30-60 词为佳>

### 歌词（粘「歌词框」）
[Intro]
[Music: 钢琴单音，雨夜环境音]

[Verse 1]
[Vocal: 贴耳气声，克制]
……
```

- **双版本/多版本**：每版各给两段，或总体两段 + 一张差异表，但两段标题一个不能少。
- **灵感模式**：仍给完整两段作「专业模式可直接粘贴版」，并附一句「也可以把整段意思浓缩成一句话丢进灵感创作框」。
- **纯音乐**：给「风格提示词」+「歌词栏指令」两块，见第三节。

### 4.1 风格栏写什么

1. **只写声音**：曲风、情绪、乐器、人声（性别/质感/音域）、制作质感；需要时可加 BPM、结构、负向约束。
2. **关键词驱动，不要小作文**：`melancholic, neo-soul, 78 BPM, rhodes, warm analog bass` 优于「一首让我想起东京雨夜霓虹灯下想念某个人的伤感歌」。
3. **客观性**：不写主观赞美（「伟大的声音」「超好听」），只写可辨识的音乐特征。
4. **结构标签的位置**：全局段落标签（`[Intro][Verse][Chorus]`）官方允许写进**歌词框**作为分段指令；本技能为便于复制，约定它们跟歌词走，不塞进风格栏——这是排版约定，不是平台限制。
5. **人声**：风格栏写「温柔女声，带轻微气声，中音区」；`[Female Vocal]` 之类演唱提示放歌词框对应段落正上方。

### 4.2 歌词标签规范（硬约束只有三条）

```
JauM:158  方括号中中文和英文都可，但要注意结构名的正确性
Jdxf:14   ⚠️与 AI 交互中请尽量使用英文名
Jdxf:71   元标签内容不区分大小写
```

✅ **硬约束**：① 用半角 `[]`；② 结构名正确（不自造「高潮段」「主歌A段」）；③ **全篇统一**（不要中英混用）。
✅ **推荐**：英文段名 `[Verse]`/`[Chorus]`/`[Bridge]`（官方「尽量使用英文名」）。
✅ **允许**：中文段名 `[前奏]`/`[主歌1]`/`[副歌]`——官方自己的示例大量使用（`JauM:171`、`WNB:176`、`FKQK:59`）。国风、情感语录等中文语境，中文段名反而更顺。
❌ **已废止**：旧版「禁用中文段名」「妙响 AI 作词默认输出中文段名，交付前需转成英文」——前者与官方冲突，后者无官方依据。

### 4.3 分段提示词格式（官方，`Jdxf:41`、`QCVK:114`）

- 每个歌词段落配一个**方括号分段指令**，**指令必须在歌词的正上方**。
- 配器与人声可分写：`[Music: …]` / `[Vocal: …]`（`MVeB:137`）。
- 段落之间空一行；即兴/旁白用 `()`（`Jdxf:74`）；歌词行数「4-8 行…无硬性要求」（`Jdxf:72`）。
- 内嵌演唱指令：`(Breath)` 呼吸 / `(Sigh)` 叹息 / `(Whisper)` 耳语 / 行尾 `...` 气声延长（`EWzn:167-173`）。
- **标点白名单**：`，！？。[] ()`，复杂符号会让 AI「唱出乱码音」（`EWzn:332`）；空格「我 在 等你」可手动造顿点（`Hio:234`）。
- **副歌前置**：官方推荐短视频/传播向用「前奏 4-8s → 核心金句 15 秒内 → 主歌 → 完整副歌」（`WNB:372-376`、`JauM:168`）。

## 五、标签速查表（英文优先；同名中文亦可）

### 5.1 结构标签

| 英文 | 中文 | 用法 |
|---|---|---|
| `[Intro]` | `[前奏]` | 建立基调，可无人声 |
| `[Verse]` / `[Verse 1]` | `[主歌]` / `[主歌1]` | 叙事主体 |
| `[Pre-Chorus]` | `[预副歌]` | 推进、制造期待 |
| `[Chorus]` | `[副歌]` | 最抓耳的核心记忆点，可前置 |
| `[Post-Chorus]` | `[副歌后]` | 副歌延伸 |
| `[Bridge]` | `[桥段]` | 中后段对比，通常只出现一次 |
| `[Interlude]` | `[间奏]` | 乐器过渡 |
| `[Instrumental]` / `[Break]` / `[Inst]` | `[伴奏]` / `[纯音乐]` | 该段无人声；**整首纯音乐时填这个字段** |
| `[Hook]` | `[钩子]` | 洗脑短句，常嵌在副歌 |
| `[Solo]` | `[独奏]` | 乐器或人声 solo |
| `[Outro]` | `[尾奏]` | 收尾，可呼应前奏 |

### 5.2 人声 / 唱法提示标签（放在段落标签下、歌词正上方）

`[Female Vocal]` `[Male Vocal]` `[Duet]` `[Choir]` `[Whispered]` `[Spoken]` `[Rap]` `[Belted]` `[Falsetto]` `[Harmonized]` `[Ad-lib]`

> 一次别堆超过 2~3 个提示标签（本技能经验），多了模型反而不知道听谁的。

### 5.3 格式纪律

1. 每个标签独占一行；标签与歌词之间空一行。
2. 段与段之间空一行。
3. 一行一句，一句一个意思。
4. 副歌每次出现把词**贴全**（本技能经验：只写一次让模型循环，结果常不一致）。
5. 全篇标签语言统一；`【主歌】`、全角括号不规范，半角 `[]` 才生效。

## 七、常见翻车与修法

| 症状 | 原因 | 修法 |
|---|---|---|
| 生成的歌没有清晰副歌、像一锅粥 | 歌词没标段落，模型猜结构 | 每段上方加 `[Chorus]` 等分段指令，指令放在歌词正上方 |
| 副歌每次回来都不一样 | 只写一次副歌指望模型循环 | 每段都贴全歌词（本技能经验） |
| 结构标签写进风格栏后没反应 | 放错框 | 分段指令移到歌词框；风格栏只留声音描述 |
| 人声发闷/不对 | 风格栏没写清人声 | 风格栏写「温柔女声中音区」；演唱提示写歌词段上方 |
| 歌词像一段话、咬字糊 | 没分行、没标签、标点太花 | 一行一句 + 标签独行 + 段间空行 + 只用 `，！？。` |
| 描述被忽略/要素丢失 | 提示词过长、堆砌冲突词 | 压到 30-60 词，只留一个主情绪和一个主风格，重写时只改 3-5 个词 |
| 纯音乐却冒出人声 | 只写了中文「纯音乐」，或压根没用字段 | 歌词栏填 `[Instrumental]`（英文）或打开纯音乐开关 |
| **某个字唱错 / 普通话串粤语** | 多音字、咬字问题 | 官方三修法：① 同音字替换后「只改编歌词，其他不动，重新生成」；② **音乐改编·翻唱**（改词保曲，参考音频权重 8-9、风格权重与创意发散尽量低）；③ 音色替换**不能**改错字。详见 `12-official-guide.md` 第六节 |
| AI 作词擅自写成 rap | 直接让 AI 根据 Beat 生成歌词 | 用明确指令「写一段符合这个伴奏的歌词…verse、chorus 等段落提示词用 [] 框起来」（`Om77:255/248`） |
| 发行时歌词里一堆标签 | 没清理就提交 | 发行前删掉方括号标签只留词 |

> 完整官方方法论与出处见 `12-official-guide.md`；押韵体系、金句公式、副歌前置结构、hook 官方依据都在那一章。
